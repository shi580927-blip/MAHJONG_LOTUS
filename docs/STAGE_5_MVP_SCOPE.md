# ЭТАП 5 — ФОРМИРОВАНИЕ MVP

**Проект:** «Маджонг: Путь Лотоса»  
**Статус:** ГОТОВО К ПРОВЕРКЕ  
**Вход:** Этап 4 утверждён пользователем вместе с PROP-401…PROP-407.

---

## 1. ЦЕЛЬ MVP

MVP должен проверить главную продуктовую гипотезу уже в реальном визуальном исполнении:

**игроку нравится сам Mahjong Solitaire, а визуальный Путь и преображение мира создают дополнительную причину пройти ещё один уровень и вернуться.**

MVP не должен доказывать ценность через количество дополнительных систем.

---

## 2. ВАЖНОЕ ОГРАНИЧЕНИЕ

60 уровней — уже утверждённое требование первой версии (DEC-005). Это больше типичного минимального MVP, однако на Этапе 5 оно сохраняется как обязательное.

Следствие:
- не сокращаем релиз до 20–30 уровней задним числом;
- архитектура и производство должны сделать создание 60 раскладок дешёвым;
- вертикальный срез на Этапе 10 может использовать только часть контента для проверки качества, но релизный MVP остаётся 60-уровневым.

---

## 3. МИНИМАЛЬНЫЙ ПОЛЬЗОВАТЕЛЬСКИЙ ПУТЬ

**Запуск → Главное меню → Продолжить/Играть → Карта Пути → Уровень → выбор пар → победа или no-moves → награда → визуальная трансформация Пути → следующий уровень → сохранение → возврат в следующей сессии**

Если этот путь не работает стабильно, остальные функции не имеют права задерживать исправление.

---

## 4. ПРИОРИТЕТЫ

- **P0 / CRITICAL** — без функции MVP не существует или не проверяет главную гипотезу.
- **P1 / DESIRABLE** — заметно улучшает качество, но при проблемах сроков может быть упрощена без разрушения core value.
- **P2 / DEFERRED** — не входит в MVP, возвращаемся после первых данных.
- **P3 / FORBIDDEN V1** — сознательно запрещено для первой версии, чтобы не раздувать продукт или не разрушать relaxing-позиционирование.

Сложность:
- **S** — низкая;
- **M** — средняя;
- **L** — высокая.

## 9. ЧТО ИМЕННО ПРОВЕРЯЕТ MVP

### Главная гипотеза
Игроку хочется продолжать не только ради очередной раскладки, но и ради визуального продвижения по Пути.

### Поэтому P0 обязательно содержит
- настоящий красивый tile feel;
- живой фон;
- карту;
- milestone-преображения;
- Lotus Pulse;
- сохранение;
- минимум рекламной монетизации;
- аналитику core funnel.

### Поэтому НЕ требуется для проверки
- магазин;
- IAP;
- коллекции;
- ежедневки;
- рейтинги;
- социальные механики.

## 10. КРИТИЧЕСКИЕ ЗАВИСИМОСТИ

1. **MVP-001 Core rules** → практически весь gameplay.
2. **MVP-003 Level data + MVP-004 solvability** → контент и доверие.
3. **MVP-009 Path + MVP-011 transformations** → главная дифференциация.
4. **MVP-020 Save** → возможность длинного 60-уровневого пути.
5. **MVP-022 Responsive** → фактическая доступность аудитории.
6. **MVP-023 Visual world + MVP-029 performance** → wow без технического провала.
7. **MVP-025 SDK** → публикация.
8. **MVP-028 event hooks** → проверка гипотезы после запуска.

## 11. ОСНОВНЫЕ РИСКИ MVP

### RISK-020 — 60 уровней увеличивают production scope
Митигировать data-driven layouts, переиспользованием символов и ограниченным числом визуальных состояний карты.

### RISK-021 — Визуальный wow может стать дороже core gameplay
Сначала tile feel и читаемость, затем декоративная насыщенность.

### RISK-022 — Petal sink может быть искусственным
На вертикальном срезе проверить, воспринимается ли пробуждение landmark как ценное действие. Если нет — роль лепестков пересматривать, а не добавлять новые sinks.

### RISK-023 — Rewarded может стать слишком выгодным
Не балансировать бесплатный прогресс вокруг обязательного просмотра.

### RISK-024 — Interstitial испортит premium mood
Точный cap определяется позже; MVP обязан поддерживать централизованную конфигурацию частоты.

### RISK-025 — Portrait может потребовать отличную композицию сцены
Не масштабировать desktop 1:1; UI/board должны перестраиваться.

## 12. РЕШЕНИЯ ЭТАПА 5 НА УТВЕРЖДЕНИЕ

### MVP-DEC-501
Релизный MVP сохраняет **60 уровней**, потому что это ранее утверждённое требование, несмотря на больший объём относительно типичного MVP.

### MVP-DEC-502
**P0 включает визуальный слой** — карта, milestone transformations, Lotus Pulse и лёгкий ambient. В этом проекте визуал не является полировкой после MVP.

### MVP-DEC-503
**IAP и полноценный магазин не входят в MVP.** Первая версия проверяет core retention и ограниченную рекламную монетизацию; платежи можно добавить после данных.

### MVP-DEC-504
**Rewarded + ограниченный interstitial входят в MVP**, потому что рекламная модель должна быть проверена в реальном продукте, но точные caps остаются конфигурационными и утверждаются позже.

### MVP-DEC-505
**Лепестки входят в MVP только как meta/progression resource.** Если на вертикальном срезе их роль не ощущается значимой, система подлежит упрощению до релиза.

### MVP-DEC-506
**Аналитические event hooks входят в P0**, даже если полный аналитический дизайн формально прорабатывается на Этапе 12.

### MVP-DEC-507
Магазин, коллекции, daily systems, лидерборды, social и live-ops **не могут задерживать релизный MVP**.
